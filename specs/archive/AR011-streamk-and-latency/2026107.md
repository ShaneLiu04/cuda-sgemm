## 0. 执行摘要

1. **1024³ 刀锋缺口的真实尺度是 1.05μs**（342.0μs vs 门线 341.0μs），而归约段占 41μs——
   任何一项归约侧微优化（省 >1.1μs）都能翻门。这不是架构性差距，是一微秒的差距。
2. **主战场是主核效率**：dsk@1024³ main 段单独折算 72.7% peak，cuBLAS 整体 84.4%——
   主核本身落后 ~12pp（2048³ 落后 ~15.6pp）。这是下一阶段的核心攻坚对象。
3. **"LDS.128 带宽墙"需要重新解读**（本报告 §2）：deep 设计点的 LSU 吞吐利用率仅 37.5%，
   72.1% 与屋顶之间的 28pp **不是带宽，是延迟覆盖/调度气泡**。acc/LDS 经验律成立的原因是
   比率 = 每 warp 延迟覆盖能力的代理变量。此修正直接改变优化方向：从"加 acc"（寄存器堆已顶，
   247/255）转向"消灭气泡"。
4. **路线图四层**：P0 测量体系解锁（TCC/ncu/锁频，一次 admin 权限）→ P1 Stream-K
   （结构性最大杠杆，消灭波量化 + 融合归约，预期 1024³ 77%+）→ P2 微优化三连
   （B 片段预取 / kk 错相 / L2 钉 C，任一项可单独翻门）→ P3 控制实验与工程卫生。
5. **一条新算的负结果预防**：大尺寸 L2 swizzle 块重排**不是杠杆**（4096³ 每波 DRAM 需求
   仅 ~21% 峰值，纯计算受限），建议作为 N7 预防性归档，避免被 CUTLASS 大尺寸经验带偏。

### 1.2 1024³ 刀锋的时间预算分解

```
dsk_sk3@1024³ 总时间 342.0μs（6279.2 GF）
  = main 段 297μs（7.23 TF = 72.7% peak，不含归约）
  + direct 归约 41μs（20MB 流量，355 GB/s ≈ 实测可达带宽 375.7 的 94.5%——流量地板）
  + kernel 启动 ~3μs
75% 门线 6298.1 GF ⇔ 341.0μs  →  缺口 = 1.05μs（0.3%）
```

**三个直接推论**：
- 归约段 41μs 中任何 >1.1μs 的节省都能翻门（L2 钉 C 预计省 4~6μs，单独翻门）；
- main 段 297μs 若吃到 B 片段预取的 +3~8%，总时间 -9~-24μs，越门余量 8~20 倍；
- cuBLAS 整体 255.7μs < 我方 main 段单独 297μs——**他们的"主核+归约"加起来比我方裸 main 还快**，
  即便他们同样必须做 K 分解（64 个 128-tile = 1.33 波，波几何不允许单核无 split 达 84%）。
  主核的 ~12pp 是真正的、尚未触到的效率空间。

## 2. 核心分析："LDS.128 带宽墙"的重新解读（待 ncu 验证）

### 2.1 指令级推演

Turing sm_75 每 SM：64 FP32 核（= 2 FFMA warp-inst/clk）、LDS 吞吐 128B/clk
（LDS.128 每 warp-inst 512B → 占 LSU 管线 4 clk）、LDS 返回延迟 ~30 clk。

deep 设计点（每 kk 步每线程 6×LDS.128 : 128 FFMA，1 block/SM = 8 warp）：

```
每 kk 步每 SM：
  LSU 管线需求 = 8 warp × 6 × 4 clk        = 192 clk    ← 利用率 37.5%
  FFMA 管线需求 = 8 warp × 128 / 2         = 512 clk    ← 屋顶
  FFMA 屋顶折算 = 65536 FLOP / 512 clk     = 128 FLOP/clk = 100% 理论峰
```

**结论：deep 的指令混合在吞吐维度根本不碰 LDS 带宽墙（37.5% 利用率，余量 2.7 倍）。
实测 72.1% 与 100% 屋顶之间的 28pp，全部是延迟覆盖/调度气泡，不是带宽。**

### 2.2 经验律的机制修正

acc/LDS 经验律（10.7→~35%、16→55-60%、21.3→72.1%）家族内严格成立：
16→21.3（比率 +33%）恰好带来 54%→72%（+33%），纯线性。机制解释修正为：

> **比率越高 = 每线程在两次 LDS 之间有越多 FFMA 可覆盖 LDS 返回延迟（ILP 自覆盖）。
> 比率是延迟覆盖能力的代理变量，不是带宽预算本身。**

旁证：swpipe 设计点（3 LDS.128 : 32 FFMA × 16 warp/SM）的 LSU 利用率 = 16×3×4/(16×32/2)
= 192/256 = **75%**——swpipe 家族确实接近带宽敏感区，而 deep（37.5%）早已远离。
两代 kernel 的"墙"其实是两种不同的墙：swpipe 接近吞吐墙，deep 是纯延迟墙。

### 2.3 优化方向的含义

- ~~继续加大 acc~~：寄存器堆已顶（247/255；TM24×TN8 = 240 acc + 寻址必 spill）；
- **正确方向 = 消灭调度气泡**，候选机制（按当前嫌疑度）：
  1. **同相停顿**：8 warp 经 `__syncthreads` 后同相进入 kk 循环，LDS 突发（48 warp-inst）
     在 MIO 队列排队，末 warp 的 LDS 返回被拉长到 ~192+30 clk；
  2. **barrier 到达歪斜**：每 tile 一次全块屏障（dbuf1 已降到 1 次/tile），LDG 方差造成
     warp 到达时间差在屏障处累积；
  3. **尾 tile 裸延迟**：最后一个 tile 无 t+1 预取，整块吃满 LDG 延迟；
  4. **kk 步内 LDS→FFMA 依赖**：`6×LDS → af/bf → 128 FFMA`（sgemm_deep.cu:167-189），
     首条 FFMA 等待 LDS 返回，同相 warp 无其他工作可填。
- **以上四项目前无法进一步分解——这正是 ncu 被 ERR_NVGPUCTRPERM 卡住造成的分析盲区，
  也是 P0 列为最高优先级的原因。** warp stall 分解（long_scoreboard / mio_throttle /
  barrier / wait）一次测量即可裁决。

## 3. 下一阶段优化路线图（P0 → P3）

### P0：测量体系解锁（一切优化前置，成本 = 一次 admin 权限）

1. **Quadro RTX 5000 切 TCC 模式**（`nvidia-smi -g 0 -dm TCC`，要求该卡不接显示器）：
   同一台 Windows 机器同时解锁 ①ncu 计数器 ②`nvidia-smi -lgc` 锁频。
2. 解锁后第一组实验（不动一行 kernel 代码，纯测量）：
   - **E-A 主核 stall 分解**：deep/dsk main 段 `smsp__average_warps_issue_stalled_*`
     四分类（long_scoreboard / mio_throttle / barrier / wait）——直接裁决 §2.3 的四候选；
   - **E-B 反向测 cuBLAS@1024³**：ncu 抓 cuBLAS kernel 的 launch config（寄存器/占用/grid
     形状/是否 split-K/归约策略）。cuBLAS 在 1024³ 达 84.4% 必然用了某种 K 分解——
     **他们的归约策略与波几何是现成答案**，一次 profile 顶一个月猜测；
   - **E-C 锁频重跑五门**（如 1860 MHz）：终结 DVFS 双域、4096³ 批间双峰、
     "分母测量下限 ±0.65pp" 三宗悬案；4096³ 的 20pp 差距先做功率归因（锁频下重测
     deep@4096³，若仍 68% 则降频嫌疑排除，纯效率缺口坐实）。

### P1：Stream-K（Kernel 10 候选，结构性最大杠杆，AR011 主菜）

**针对的两个结构性浪费（量化）**：

| 浪费 | 现状 | 代价 |
|---|---|---|
| 波量化尾波 | 2048³ deep：128 blocks / 48 SM = 2.67 波 → 尾波效率 88.9% | **-11%** |
| 归约独立第二 kernel | dsk@1024³：归约 41μs + 启动 ~3μs；归约流量已在地板（355 GB/s = 可达带宽 94.5%，ILP/提示词全无效是物理必然） | **-13%（1024³）** |

**Stream-K 设计要点**：
1. 把 (tile_x × tile_y × k-step) 三维迭代空间切成**恰好 48×W 个连续块**，每块负责变长
   K 区间——任意尺寸波填充率 100%；
2. 每 C-tile 的最后完成块持 **per-tile 票据**（atomic ticket），以**固定 z 序**读其他块的
   部分积、累加自己的寄存器累加器直写 C：
   - 自己的部分积**不经 DRAM 往返**（省 P 写+读各一片，1024³sk3 等效省 ~8MB 往返）；
   - C 读回合消除（自己的贡献在寄存器里，`C = own_acc + Σ P_others`）；
   - **确定性保持**：固定 z 序求和 + 加法链与现归约同序 → run-to-run 逐位确定
     （bitwise 锚链可延续，21/21 专项可扩展覆盖）；
3. **实现成本低于想象**：`deep_tile_grid` 的 `t0/t1` 参数化（sgemm_deep.cu:93-94，
  "z 切片 + 变长 k-tile 区间"）已是 Stream-K 块映射的雏形——主体 compute/流水/布局/模板
  全部复用，新写只有 ①块→(tile, k-range) 连续切分函数 ②epilogue 票据 + 固定序归并。

**翻案说明**：AR008 曾否决"atomic last-block 融合（单块串行化）"——被否决的是
**全局单块**归约方案；**per-tile 票据**（96 块各自归约自己的 256×128 区域，块间并行）
不存在串行化，是该否决的正确变体，且有 CUTLASS split-K semaphore 先例。

**预期**（保守/中性）：

| 尺寸 | 现状 | Stream-K 后 | 依据 |
|---|---|---|---|
| 1024³ | 342.0μs（74.77%） | ~300μs（**77%+，越门且余量大**） | -41μs 归约段折叠为 ~25μs 尾部归并 + 启动消除 + P 自片往返消除 |
| 2048³ | 1.003ms（82.6%） | 波效率 88.9→~97% 叠加（+6~9%） | 128 blocks → 144（3 整波）无尾波 |
| 512³/256³ | swsk 守擂 | auto 继续守 swsk（不动） | Stream-K 在 2-8 tile 尺度无优势 |

**风险与对策**：尾块不均衡（最后完成块多干归并活 → kernel 尾部 ~5μs 拉长，可接受）；
票据原子开销（每 tile 一次 atomicInc，48-512 次/kernel，可忽略）；部分积可见性
（`__threadfence` + acquire 语义，racecheck 专项覆盖）。

### P2：微优化三连（便宜、可独立消融、任一项可能单独翻 1024³ 门）

#### P2.1 kk 步内 B 片段寄存器预取（+8 regs 刀口实验）

- **现状**：compute 循环每 kk 步 `6×LDS → af/bf → 128 FFMA`，LDS 返回延迟（~30 clk）
  在步首裸露（§2.3 候选 4）。
- **改法**：B 片段(kk+1) 先 LDS 入第二组寄存器，在 kk 的 128 FFMA 期间覆盖其延迟
  （经典双缓冲片段流水）。A 是 warp 级广播 LDS（延迟特性更好）可后置不做。
- **成本**：+8 寄存器（dbuf1 实例 243 → 251/255，刀口但零 spill 可行；若 ptxas 重排则
  按军规逐实例审计——AR010 教训直接适用）。
- **预期**：+3~8% main（若 §2 同相停顿/步首延迟假说成立）；也可能 ~0（若气泡主体在
  barrier 歪斜）——**这正是需要消融裁决的科学问题**。
- **消融设计**：`--dbuf 1` 固定，A/B 两组构建（预取 on/off 模板），paired v4 协议
  1024³/2048³ 配对，ptxas 审计门（0 spill + 寄存器数记录）。

#### P2.2 kk 轮转错相（零寄存器成本，打破 8 warp 同相）

- **现状**：8 warp 经屏障后**同相**执行 kk 循环——同时发 LDS、同时停顿、同时 FFMA，
  调度器在停顿窗口无活可派（§2.3 候选 1）。
- **改法**：warp w 的 kk 处理序轮转偏移（`kk' = (u + w) & 7`，u = 0..7 展开循环）。
  kk 步彼此独立（acc 累加可任意 kk 序），合法性无虞；LDS 地址按 kk' 取，布局不变。
- **成本**：**零寄存器**（w 偏移量免费）。
- **代价（必须明示）**：每元素 c[i][j] 的 k 加法序改变 → **与 deep/swpipe 不再逐位一致**
  （仍 rel≈1e-7 正确、run-to-run 逐位确定）。按"新变体"立数值口径：正确性走 rel≤1e-4
  双参考门，确定性走双跑逐位门；bitwise 锚链（deep==swpipe 等 21 项）不适用于本变体，
  需在 srs 中预先声明，避免破坏既有锚链的解释力。
- **预期**：+0~5%（同相停顿若真占 5-10% 的墙钟则兑现）。
- **消融设计**：模板 <WARP_STAGGER> 双实例，同上配对协议。

#### P2.3 L2 persistence window 钉 C（三行代码，单独翻门）

- **现状**：dsk direct 归约读 C（4MB@1024³）走 DRAM——而 **C@1024³ = 4MB 恰好等于
  TU104 L2 容量**，A/B 流对它的驱逐是纯损耗。
- **改法**：`cudaStreamSetAttribute` 的 accessPolicyWindow 把 C 区域设 persisting
  （hitRatio 调优，如 0.6-1.0），main+归约同流执行。
- **成本**：~3 行代码 + hitRatio 消融；对 kernel 主体零侵入。
- **预期**：归约 41μs 中 C 读占 ~9μs 量级，省 4~6μs——**单此一项越过 1.05μs 门缺口**。
- **风险**：persisting 窗口挤压 A/B 的 L2 正常命中率（A/B 面板复用受影响）——需 main 段
  同会话对照，净效应裁决；`cudaDeviceSetLimit(cudaLimitPersistingL2CacheSize)` 需设上限。
- **消融设计**：`--rv2 0` 固定，{persistence on/off} × {1024³}，看 main/reduce 分段
  verbose 计时（dsk 已有分段计时基建，sgemm_deep_sk.cu:99-136）。

### P3：控制实验与工程卫生

1. **16-warp 控制实验（科学价值最高的研究项）**：8×8 acc / 2 block / 16 warp 几何在本
   家族只做到 54-60%（vec4），但其延迟覆盖天然更好（4 warp/调度器 vs deep 的 2）。
   用 deep 级流水工艺（dbuf 单同步 + P2.1 片段预取）重做一版 8×8：
   - 若逼近 72% → 经验律需改写（比率效应 ≈ 流水质量效应），且更细 tile 粒度
     （128×128 → 4 倍块数）改善非方阵/中等尺寸的波量化；
   - 若仍 ~60% → 比率的延迟覆盖机制坐实，deep 几何就是本寄存器堆的甜蜜点。
   - LSU 利用率核算：16 warp × 4 LDS × 4 clk / (16×64/2) = 256/512 = 50%——
     吞吐安全，纯延迟实验。
2. **4096³ 先归因再动手**：锁频（P0-E-C）下重测；若仍 68% → 降频嫌疑排除。**注意：
   L2 swizzle/块重排在此不是杠杆**——大 GEMM 在本 GPU 上纯计算受限：
   ```
   deep@4096³ 每波（48 块）DRAM 需求 ≈ 2 A 面板(8MB) + 48 B 面板(96MB) ≈ 104MB
   波耗时 ≈ 1.1ms → 带宽需求 ≈ 95 GB/s = 448 GB/s 峰值的 21%
   ```
   建议将"L2 swizzle 非杠杆（大尺寸 FP32 GEMM、本 GPU）"作为 **N7 负结果预防性归档**。
3. **工程卫生（半天内可清）**：
   - `sgemm_deep_sk.cu:15-17,109` 头注释仍写"P 片 `__stwt` 写穿"——与已回退的实测
     （sgemm_deep.cu:215-216 统一默认 store）**互相矛盾，属过时注释**，违反注释契约，应修；
   - 同文件 "归约 45→~33μs" 与实测 43μs 的口径不一并修；
   - ws/wsk 的 4×8B spill 长期按"既有基线"豁免——教学阶梯的卫生债，可根治或显式记录豁免；
   - auto 的 sk 按 128-几何带判取**固定值**（≤4→sk6 / ≤64→sk3），矩形/极端长宽比尺寸
     换几何公式 `sk = clamp(ceil(48·W / blocks), 2, 16)` 泛化（当前 1000×1016 等近方阵
     已覆盖，长宽比 >4:1 的尺寸未验证）。
